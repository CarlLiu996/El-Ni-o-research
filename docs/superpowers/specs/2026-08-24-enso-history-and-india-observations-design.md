# ENSO 历史复盘与印度观测指标设计

## 目标

在不把工作簿重新膨胀为多张原始数据表的前提下，为现有“气候天气 → 供给基本面 → 市场定价 → CTA 可捕捉性 → 数据审计 → 配置结论”研究链增加两项能力：

1. 持续更新印度季风累计降雨偏差、官方季风起退事件和印度糖蔗主产区 NDVI 代理；
2. 用统一、无未来函数的口径复盘历次厄尔尼诺，并把历史规律作为当前 CTA 配置结论的置信度修正，而不是替代当前的 L1—L4 门槛。

最终交付为可重复生成的八页研究工作簿、结构化 CSV、自动刷新任务、质量检查和研究说明。用户已在 GitHub Actions 中配置 `EARTHDATA_TOKEN`；代码不得读取后输出、记录或提交该 Secret。

## 设计原则

- 研报只用于提出变量和假设，所有表内数值必须来自可审计外部数据或项目计算。
- 观测、预测和历史统计必须分列，预测数据不得与已实现数据混算。
- 历史复盘只使用在当时可获得的数据；当前事件标记为“进行中”，不得读取未来峰值、最终单产或事后价格。
- 上游气候信号不能绕过供给、价格和 CTA 门槛直接触发加仓。
- 长历史现货价格只能生成研究代理，不得标记为可部署期货 CTA 回测。
- 缺失、鉴权失败或半结构化解析失败时保持缺失并降低置信度，不用推算值冒充官方值。
- 原始长序列存入 CSV；工作簿只保留八张可见 Sheet，并在每张表内提供必要的近期历史和迷你趋势。

## 数据源与指标口径

### 1. 印度季风累计降雨偏差

来源沿用 NASA POWER 日频 `PRECTOTCORR`，覆盖现有三个印度糖区代表点：Maharashtra、Uttar Pradesh、Karnataka。历史请求范围扩展到 1981-01-01 至刷新日。

计算规则：

- 每年季风累计窗口为 6 月 1 日至 9 月 30 日；季节进行中时累计至刷新日。
- 每个代表点先计算累计降雨，再对有效代表点等权平均，避免观测缺失改变日度权重。
- 历史正常值使用 1991—2020 年相同季节进度的累计降雨均值。
- `cumulative_departure_pct = current_cumulative / climatology_cumulative - 1`。
- 至少两个代表点完整覆盖计算窗口才产生区域值；否则指标为缺失。
- 同时输出当前累计量、历史正常值、偏差、历史分位、有效点数、季节状态和数据截至日。

该指标是项目自算的主产区代理，不声称等同于 IMD 全国或分区官方累计距平。

### 2. 季风开始与退出时间

官方事件来源为 India Meteorological Department 的新闻稿、季风进展页面和公告 PDF。由于没有稳定数值 API，接入方式是带来源留痕的半结构化事件抓取。

口径固定为：

- 开始：IMD 正式宣布西南季风抵达 Kerala 的日期；
- 退出：IMD 正式宣布西南季风开始从印度西北部撤退的日期；
- 正常日期与版本来自 IMD 方法说明，作为有来源版本的配置数据，不在公式中无来源硬编码；
- 输出事件类型、官方日期、正常日期、偏早/偏晚天数、公告发布日期、抓取时间、原始 URL、解析状态和人工复核状态。

解析器只接受包含明确官方动作和日期的公告。若页面结构变化、文本模糊或同季节出现冲突日期，状态设为 `REVIEW_REQUIRED`，不生成偏早/偏晚结论。工作流每日检查，但一个季节只在新公告出现时增加事件记录。

### 3. 印度甘蔗 NDVI／长势代理

来源为 NASA LP DAAC 的 MODIS 061 `MOD13Q1`，250 米、16 日一期。使用 Earthdata bearer token 访问数据，Token 只从 `EARTHDATA_TOKEN` 环境变量读取。

第一阶段明确标记为“印度糖蔗主产区 NDVI 代理”，不标记为糖蔗专属遥感单产指标：

- 在三个现有主产区代表点周围使用固定 50 公里分析缓冲区；
- 仅保留 MODIS 质量标记为 good quality 的像元；
- NDVI 原始整数乘以 0.0001，剔除产品定义的填充值和非法范围；
- 每个 16 日合成期先算各缓冲区中位数，再对三个区域等权平均；
- 使用 2001—2020 年相同合成期建立历史均值、标准差和分位分布；
- 输出当前 NDVI、同期差值、同期 z-score、历史分位、有效像元比例、区域覆盖数、产品日期、发布/下载时间和来源粒度。

若 Token 缺失、过期、产品尚未发布或有效像元比例低于 30%，最新值不参与当前结论。取得可靠糖蔗种植掩膜后，才能升级为种植面积加权的“糖蔗专属 NDVI”；本期不把行政区或缓冲区植被误称为糖蔗。

## 历次厄尔尼诺复盘方法

### 事件目录

历史已完成事件使用 NOAA CPC ONI 统一识别：连续至少五个重叠三个月季节达到 `ONI >= 0.5°C`。事件记录开始季、峰值季、结束季、持续季数和峰值强度。当前 2026 过程继续使用项目实时 RONI、SOI 和 ONI 观察，标记为 `ONGOING`；未满足完整事件条件前不混入已完成事件胜率统计。

### 统一证据链

每个历史事件形成一行审计面板：

1. **L1 气候天气**：ONI 峰值、持续时间、SOI/DMI 状态、印度季风累计偏差、印马和巴西主产区降雨/根区湿度异常；NDVI 仅覆盖 2000 年以后事件。
2. **L2 供给基本面**：FAOSTAT 的油棕果、甘蔗产量、面积和单产。主要国家为印度、巴西、印度尼西亚和马来西亚。每项同时计算事件年同比及相对事件前五年中位数的偏差，不用未来年份拟合趋势。作物年与自然年无法严格对齐时明确标记。
3. **L3 市场定价**：World Bank Pink Sheet 月度棕榈油和糖价格，计算事件开始后 0—3、3—6、6—12 个月价格变化、最大上涨和最大回撤。该价格是全球现货/基准代理，不包含期货展期收益。
4. **L4 CTA 可捕捉性**：全部事件使用月频价格代理构造近似 Medium（3/6 月）与 Slow（6/12 月）时间序列动量，信号滞后一月，年化目标波动率 20%，最大绝对杠杆 2 倍，单边换手成本 2 bps。2015 年以后事件另外使用现有 P/SR 日频 Fast 20/60、Medium 60/120、Slow 120/250 CTA Proxy。两套结果分列并标注，禁止拼接为一个业绩序列。
5. **L5 数据审计**：记录每个事件各层覆盖率、数据发布日期可得性、代理口径和缺失原因。

### 历史规律与当前匹配

历史规律按棕榈油链和白糖链分别总结，不输出笼统的“农产品平均效应”。

- 至少四个有效历史事件且同方向比例达到 70%，才描述为“较稳定历史模式”。
- 三个有效事件只描述为“有限样本倾向”。
- 少于三个有效事件显示“证据不足”，不计算有意义的胜率。
- 当前相似事件仅依据刷新日已经观察到的 ONI/RONI 强度、DMI 方向、主产区累计降雨偏差和已经发布的供给状态筛选。
- 相似事件少于三个时，历史模块只能提供案例提示，不能提高 CTA 配置等级。
- 历史结果只修正结论置信度；当前 L2 未收紧或 L3/L4 未确认时，历史相似性不能把 `KEEP_MONITORING` 升级为主题加仓。

## 数据文件和模块边界

新增结构化文件：

- `data/processed/climate/india_monsoon_cumulative.csv`
- `data/processed/climate/india_monsoon_events.csv`
- `data/processed/climate/india_sugar_ndvi.csv`
- `data/processed/history/enso_events.csv`
- `data/processed/history/event_evidence_panel.csv`
- `data/processed/history/event_cta_summary.csv`
- `data/processed/history/current_event_comparison.csv`

新增或扩展的代码单元：

- `src/elnino_cta/sources/imd.py`：下载、解析和审计 IMD 官方事件公告；
- `src/elnino_cta/sources/earthdata.py`：发现、下载和聚合 MOD13Q1；
- `src/elnino_cta/sources/faostat.py`：获取作物年度产量、面积和单产；
- `src/elnino_cta/sources/world_bank.py`：获取 Pink Sheet 月度价格；
- `src/elnino_cta/historical_review.py`：识别事件、建立证据面板、计算历史规律和当前匹配；
- `src/elnino_cta/monitoring.py`：加入新增指标的时效、覆盖和结论门禁；
- `scripts/build_research_workbook.mjs`：把当前仓库外的七页生成逻辑迁入仓库，按监控日期生成八页工作簿；
- `.github/workflows/monitor.yml`：在已有刷新后调用外部指标、历史复盘和工作簿生成步骤。

每个数据源适配器只负责下载和标准化；历史统计不写进下载器；Excel 生成器只读取已处理 CSV 和监控快照，不在构建时联网。

## 工作簿结构

工作簿保留八张可见 Sheet：

1. `00_结论-CTA建议`：结论、执行动作、历史相似样本、升级/降级条件和置信度；
2. `01_总逻辑`：加入“当前证据链”和“历史校准”两条输入，但历史校准只能调整置信度；
3. `02_H_历次厄尔尼诺复盘`：事件矩阵、棕榈油/白糖分链规律、当前阶段匹配、样本量和限制；
4. `03_L1气候天气`：加入累计季风偏差、官方起退事件、NDVI 代理及其迷你趋势；
5. `04_L2供给基本面`：保留当前产量、需求、库存、加工分流和政策否决项；
6. `05_L3市场定价`：保留 P/SR 当前价格、波动和期限结构，同时明确全球历史代理不参与当前国内合约定价门槛；
7. `06_L4_CTA环境`：统一 20% 目标波动，分开展示历史月频代理和当前日频 P/SR 结果；
8. `07_L5数据审计`：显示来源、频率、最新观测、发布日期、时滞、覆盖、鉴权/解析状态和是否参与结论。

长期历史数据放在各相关 Sheet 的下方审计区域并用于迷你折线图，不新增可见 Raw Sheet。每个指标继续包含当前值、同季节位置、指标含义、当前位置含义、来源、限制和数据日期。

## 失败处理与安全

- `EARTHDATA_TOKEN` 只通过环境变量读取；日志、异常、manifest 和工作簿不得包含 Token、请求头或带凭据 URL。
- Token 失效时 NDVI 状态为 `AUTH_REQUIRED`，其余数据和工作簿仍可生成。
- IMD 页面结构变化时保留原始 URL 和解析失败原因，事件值为缺失；不静默沿用上一季日期。
- 外部服务临时失败时保留最近一次已发布数据及其真实 `published_at`，并按阈值标记 `STALE`；不得把刷新时间当发布日期。
- FAOSTAT 或 World Bank 历史修订导致结果改变时，manifest 记录下载时间、来源版本或文件哈希。
- 任何年度预测值必须在字段中标为 `forecast`，历史复盘的已实现统计只使用 `actual`。

## 验证与验收

自动化测试至少覆盖：

- 季风累计窗口、跨年、1991—2020 基准和缺失代表点门槛；
- IMD 公告解析的正常、冲突和页面变更样例；
- MODIS 缩放、质量掩膜、合成期匹配、有效像元率和 Token 脱敏；
- ONI 五季事件识别、当前未完成事件排除和事件窗口边界；
- FAOSTAT 粒度、单位、重复键及自然年限制；
- 月频趋势代理的下一期执行、20% 目标波动、2 倍上限和成本；
- 历史规律的最小样本门槛与当前结论不可越级规则；
- 所有新增 CSV 的主键唯一性、空值、日期、范围、时效和来源字段；
- 工作簿八张可见 Sheet、顺序、关键表格、迷你趋势、公式错误扫描和视觉预览；
- 仓库 secret scan，确认代码、CSV、日志和 Excel 中不存在 Earthdata Token。

验收完成的定义是：在本地无 Token 时可降级生成明确标记的工作簿；在 GitHub Secret 可用时自动刷新 NDVI；三项印度指标和历史事件面板均有来源、时效和质量状态；最新版八页 Excel 能从仓库内脚本重复生成；当前 CTA 建议可追溯到每层证据且不会被历史相关性越级覆盖。
